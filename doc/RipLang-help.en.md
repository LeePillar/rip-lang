# Rip Language Manual

> [中文](RipLang-help.md) | **English**

Rip is a strongly typed, fully explicit, server-oriented language. This manual covers only **how to write, use, and ship** it, organized as variables → syntax → components → projects → commands, and works as a quick reference.

> The search box in the top-right corner searches titles and body text (press `/` to focus). The sidebar highlights as you scroll. Every code block can be copied with one click.

## 1. Five-Minute Quick Start

```bash
rip version                    # 确认工具链可用
rip new shop --template http   # 生成项目骨架
cd shop
rip run main.rp                # 启动服务：http://127.0.0.1:8080/
rip check main.rp              # 只做静态检查
rip build main.rp              # 编译原生二进制到 dist/
```

The project layout generated by `rip new`:

```text
shop/
├── rip.toml      # 项目清单（名称、版本、入口、服务端参数）
├── main.rp       # 入口，必须含 func main() -> void
└── .gitignore
```

The smallest HTTP service:

```rp
mod shop;

use std::http;

#[get("/")]
func index(read req: http.request) -> http.response {
    return http.response[status = 200, json = [message = "Hello, Rip!"]];
}

func main() -> void {
    let routes: vec<http.route> = [];
    http.serve(8080, http.router(routes));
}
```

Remember six rules:

| Rule | Description |
| --- | --- |
| Single form | One syntax per meaning; no aliases |
| All types explicit | Variables, parameters, return values, fields, and container elements all need types |
| Statements end with ; | Blocks and function declarations do not |
| Four loops | loop / while / while let / for ... in, same rules as Rust |
| No class | Use ary (fixed-field struct) + free functions |
| No inference | No :=, no omitted parameter types |

## 2. How to Define Variables

Four bindings, all written as statements, with explicit types:

```rp
let name: string = "rip";        // 不可变
let mut count: int = 0;          // 可变
const MAX: int = 1024;           // 模块级编译期常量
static APP: string = "shop";     // 模块级静态值（启动时初始化）
```

Rules:

- A `let` binding cannot be reassigned; use `let mut` for variables that change.
- `const` / `static` are module-level only (outside functions), cannot be reassigned, and there is no `static mut`.
- No duplicate names in the same scope (no shadowing).
- To modify an `ary` field or call container-mutating methods such as `push` / `set`, the root variable must be `let mut`.
- Naming: variables/functions/types use `snake_case`, constants/statics use `SCREAMING_SNAKE_CASE`.

```rp
let mut total: int = 0;
total = total + 1;      // 合法

let fixed: int = 10;
// fixed = 11;          // 编译错误：不可变
```

### 2.1 Type Overview

| Type | Syntax | Description |
| --- | --- | --- |
| Integer | int (= i64) / i8 / i16 / i32 / i64 | int by default; bit widths match Rust |
| Unsigned integer | u8 / u16 / u32 / u64 | Same semantics as Rust |
| Float | float | 64-bit |
| String | string | UTF-8, immutable; single quotes denote one character |
| Boolean | bool | true / false |
| Struct | [id: int, name: string] | ary, fixed fields |
| Sequence | vec\<T\> | Ordered, indexes start at 0 |
| Dictionary | map\<K, V\> | Dynamic keys |
| Nullable | option\<T\> | some(x) / none |
| Result | result\<T, E\> | ok(x) / err(e) |
| Any | any | Only at JSON / dynamic-dictionary boundaries |

Conversions between integer types must be explicit:

```rp
let a: u32 = 0xFF;
let b: int = a.to_int();
let c: u8 = b.to_u8();
```

A prefix only denotes the radix (`0x` / `0o` / `0b`); the type is a suffix (`42i32`, `7u8`). Integers without a suffix are `int`, decimals are `float`.

### 2.2 The Three Data Structures

**ary: fixed-field struct**

```rp
type address = [city: string, zip: string];
type user = [id: int, name: string, address: address];

let mut u: user = [
    id = 1,
    name = "张三",
    address = [city = "北京", zip = "100000"]
];

u.name;                 // 读
u.address.city;         // 嵌套读
u.name = "李四";         // 写，u 必须是 let mut
```

Fields are accessed with dots; `u["name"]` and `u[0]` are forbidden; the field set is fixed at compile time.

**vec: ordered sequence**

```rp
let nums: vec<int> = [1, 2, 3];
let empty: vec<int> = [];
let mixed: vec<string, int> = ["a", 1];   // 定长异构，只读

nums.0;        // 编译期常量下标
nums.at(1);    // 运行时下标，返回 result<int, string>
nums.len();
```

`nums[0]` is forbidden; index with `.0` (constant) or `.at(i)` (runtime).

**map: dynamic dictionary**

```rp
let mut scores: map<string, int> = [];
scores.set("张三", 90);
scores.get("张三");     // option<int>
scores.has("张三");     // bool
scores.delete("张三");  // option<int>

let config: map<string, string> = ["name" = "shop", "city" = "北京"];
```

`scores["alice"]` is forbidden; always use `.get` / `.set` / `.has` / `.delete`.

Choosing between them: fixed fields use `ary`, ordered indexing uses `vec`, dynamic keys use `map`; there are no implicit conversions.

### 2.3 option and result

```rp
let found: option<int> = some(1);
let missing: option<int> = none;

let ok_value: result<int, string> = ok(1);
let bad_value: result<int, string> = err("boom");
```

- `option<T>`: `.unwrap_or(x)`, `.unwrap()`, `.is_some()`, `.is_none()`.
- `result<T, E>`: `.unwrap_or(x)`, `.unwrap()`, `.unwrap_err()`, `.is_ok()`, `.is_err()`.

### 2.4 Named and Recursive Types

```rp
type user = [id: int, name: string, tags: vec<string>];
type node = [value: int, children: vec<node>];   // 递归：经 vec 间接自引用
```

- Type definitions cannot change at runtime; type names are unique within a file.
- Recursive types must reference themselves indirectly through containers such as `vec` / `option` / `map`; pure alias cycles (`type a = b; type b = a;`) are rejected.

### 2.5 Generic Functions

```rp
func identity<T>(x: T) -> T {
    return x;
}

func size<T>(read items: vec<T>) -> int {
    return items.len();
}

let n: int = identity(1);              // 从实参推断
let s: string = identity<string>("a"); // 显式类型实参（推断不出时用）

// 约束：S 必须实现 shape，函数体内可以调用接口方法
func total_area<S: shape>(read items: vec<S>) -> float {
    let mut sum: float = 0.0;
    for item in items {
        sum = sum + item.area();
    }
    return sum;
}
```

- Type arguments can be omitted (inferred from arguments) or written explicitly as `f<T>(...)`; an explicit list must be complete.
- The constraint `<T: interface name>` determines which methods the function body may call; an unconstrained T can only be passed around as a whole.
- Runtime type erasure keeps a single implementation; AOT output from `rip run` and `rip build` behaves identically.

### 2.6 Copy and Move

| Type | Semantics |
| --- | --- |
| int\* / float / bool | Copy; assignment and argument passing copy automatically |
| string / ary / vec / map / closures | Move; the original variable becomes invalid after assignment or pass-by-value |

```rp
let a: vec<int> = [1, 2];
let b: vec<int> = a;        // a 被 move，此后不能再用 a
let c: vec<int> = b.clone(); // 需要两份时就 clone
```

Function parameters are Copy / Move by default; write `read` when you do not want to give up ownership:

```rp
func total(read items: vec<int>) -> int {   // 只读借用，调用方保留 items
    return vec.sum(items);
}

func add_one(write counter: int) -> void {  // 可写借用，实参必须是 let mut
    counter = counter + 1;
}
```

### 2.7 Enums (ADT)

```rp
type status = enum {
    active,
    pending,
    banned(reason: string),
}

let s: status = status.active;
let b: status = status.banned[reason = "spam"];
```

- Variants are separated by `,`; field-less variants are just names, variants with fields use `name(field: type, ...)`.
- Construct with `enum.variant` / `enum.variant[field = value]`; every field is required and types must match.
- Enums are Move types; use `.clone()` when you need two copies.
- Enums can carry methods: `func status.blocked(read s: status) -> bool`, called as `s.blocked()`.
- Fields of an enum value cannot be read directly (`s.reason` is an error); destructure with `match`.
- Serialized to JSON as `{"variant": "banned", "reason": "spam"}`.

## 3. Syntax and Control Flow

### 3.1 Operators

```text
+  -  *  /  %       算术（同类型，结果同类型；零除 panic）
== != > >= < <=     比较（同类型，返回 bool）
&& || !             逻辑（短路）
+                   字符串拼接（两侧都是 string）
```

Precedence from low to high: `||` → `&&` → comparison → `+ -` → `* / %` → unary `! -`.

### 3.2 if

```rp
if score >= 90 {
    print("A");
} else if score >= 80 {
    print("B");
} else {
    print("C");
}
```

Conditions must be `bool` (no truthy/falsy); parentheses are optional, braces are required.

### 3.3 Loops: Four Forms (same rules as Rust)

There are only these four loops; pick one per use case and do not combine it with other syntax.

```rp
// while：条件成立就继续，最常用的计数 / 条件循环
let mut count: int = 0;
while count < 10 {
    print(count.to_string());
    count = count + 1;
}

// loop：一直循环，退出条件写在循环体里
let mut i: int = 0;
loop {
    if i >= 10 { break; }
    print(i.to_string());
    i = i + 1;
}

// for ... in：遍历 vec（得到元素）或 map（得到 key）
let tags: vec<string> = ["a", "b"];
for tag in tags {
    print(tag);
}

let mut scores: map<string, int> = ["math" = 90];
for key in scores {          // key: string
    print(key);
}

// while let：每轮取一个值并匹配模式，取不到就结束
while let some(value) = cache.get("key") => {
    print(value);
    cache.delete("key");       // 删掉后下一轮 get 返回 none，循环结束
}
```

**break / continue** (works in all four loops; affects only the innermost one):

```rp
let mut k: int = 0;
while k < 10 {
    k = k + 1;
    if k == 2 { continue; }    // 跳过本次，回到条件判断
    if k == 5 { break; }       // 直接结束循环
    print(k.to_string());
}
```

| Scenario | Which loop | Syntax |
| --- | --- | --- |
| Fixed count / counting | while | `while i < n { ...; i = i + 1; }` |
| Exit condition in the middle | loop | `loop { ... if done { break; } }` |
| Iterating a vec / map | for ... in | `for x in xs { ... }` |
| Draining an optional value until empty | while let | `while let some(v) = next() => { ... }` |

- Loop conditions must be `bool`; no truthy / falsy.
- There is no `do-while` and no C-style three-part `for`; write `while` for conditional loops.
- In `while let`, `=` binds a pattern and `=>` introduces the body (`=>` occurs only here and in `match` arms).
- `while let` is typically used for calls such as `cache.get` and `map.delete` that return `option`.

### 3.4 match

```rp
match opt {
    some(v) => { print(v.to_string()); }
    none => { print("empty"); }
}

match res {
    ok(v) => { print(v.to_string()); }
    err(e) => { print("error: " + e); }
}
```

- Arms use `=>` (pattern on the left, body on the right); `=` is only for binding and assignment; arm bodies require braces.
- `option` must cover both `some` / `none`, and `result` must cover `ok` / `err`; a missing arm is a compile error.
- Destructuring a struct:

```rp
match user {
    [id: int, name: string, address: _] => {
        print(name);
    }
}
```

An enum must cover every variant:

```rp
match state {
    status.active => { print("ok"); }
    status.pending => { print("wait"); }
    status.banned[reason: string] => { print(reason); }
}
```

- Enum patterns are written `enum_name.variant`; variants with fields bind them via `[field: type, ...]` (`_` binds nothing).
- Omitting any variant is a compile error: `match on enum 'status' must cover variant 'banned'`.

### 3.5 `?`: Propagating Errors

```rp
func read_config(path: string) -> result<string, string> {
    let content: string = fs.read_file(path)?;
    return ok(content);
}
```

`?` may only be used in functions returning `result`; on `err` it returns immediately, on `ok` it unwraps the value and continues. Inside a function whose return type is not `result`, using `?` is a compile error.

### 3.6 Declaring and Calling Functions

```rp
func add(a: int, b: int) -> int {
    return a + b;
}

func log_message(msg: string) -> void {
    print(msg);
}

func main() -> void {
    let sum: int = add(1, 2);
    log_message("sum=" + sum.to_string());
}
```

- Each parameter is written `name: type`; the return type is mandatory — write `-> void` when nothing is returned.
- Overloading, default parameters, and variadic parameters are not supported.
- Functions may be declared after `main`; all are registered before execution.

**Visibility**: `self func` is visible only within the same package (same directory); `pub func` / `pub type` are exported to other packages. Functions without a modifier stay globally visible.

**Closures**: parameter and return types must be written, and all types must be explicit:

```rp
let double: func(int) -> int = func(x: int) -> int {
    return x * 2;
};
```

**Three call forms** (memorize these three and you can call anything):

```rp
add(1, 2)                    // 1. 普通函数：直接写名字
http.serve(8080, handler)    // 2. 标准库：use 后用「别名.函数」
items.push(3)                // 3. 值的方法：值.方法()
```

Standard-library imports can be aliased:

```rp
use std::http;
use std::sys as sys;
use rust::serde_json as json;
```

### 3.7 Annotations (Above Functions)

| Annotation | Effect | Example |
| --- | --- | --- |
| #[get("/path")] etc. | Registers an HTTP route | #[post("/users")] |
| #[interval("5m")] | Scheduled task | Intervals use ms / s / m / h / d |
| #[test] | Test function, run by rip test | No parameters, no arguments, returns void |
| #[bench] | Benchmark function, run by rip bench | No parameters, no arguments, returns void |

Route handlers have a fixed signature: `func(read req: http.request) -> http.response`.

### 3.8 Methods and Interfaces

Attaching methods to a type: `func Type.method(receiver, ...)`; the receiver is `read` (read-only) or `write` (mutable).

```rp
type user = [id: int, name: string];

func user.display(read u: user) -> string {
    return u.name;
}

func user.rename(write u: user, name: string) -> void {
    u.name = name;
}

let mut u: user = [id = 1, name = "张三"];
print(u.display());
u.rename("李四");
```

- You simply call `u.display()`; no extra syntax is needed.
- A `write` method can only be called on a `let mut` variable.
- Method names are unique per type; the fully qualified name is `user.display`.

**Interfaces**: declare a set of methods; any type implementing them can be used as that interface.

```rp
type shape = interface {
    func area() -> float
    write func scale(factor: float) -> void
}

type circle = [radius: float];

func circle.area(read c: circle) -> float {
    return 3.0 * c.radius * c.radius;
}

func circle.scale(write c: circle, factor: float) -> void {
    c.radius = c.radius * factor;
}

let shapes: vec<shape> = [circle[radius = 1.0]];
for s in shapes {
    print(s.area().to_string());
}
```

- No implements clause is needed: matching method names, parameters, and return types implement the interface automatically.
- Interfaces can be stored in `vec` and used as parameters / return values; calls resolve the method on the real type automatically.
- Interface values are created with named constructors (`circle[radius = 1.0]`), which is how the runtime records the type.

### 3.9 defer: Cleanup on Function Exit

`defer call;` postpones a call until **the current function exits**; use it to close connections, unlock, or delete temporary files.

```rp
func save(path: string, text: string) -> result<void, string> {
    let f: file = fs.open(path)?;
    defer f.close();            // 实参在 defer 处就地求值
    f.write(text)?;
    return ok;
}
```

- Only calls are allowed: `defer f(...)` / `defer x.m(...)` / `defer module.f(...)`.
- Arguments are evaluated on the `defer` line, so changing the variable later does not affect the captured value.
- Multiple `defer` calls run last-in-first-out: the last one registered runs first.
- They run on normal return, on `return`, on early return via `?`, and on runtime errors.
- Each function runs only its own `defer` calls; when an inner function returns it cleans up only its own entries.

```rp
func demo() -> void {
    defer print("first");        // 最后执行
    defer print("second");       // 先执行
    print("body");
}
// 输出：body / second / first
```

### 3.10 async / await: Asynchronous Tasks

`async func` declares a task function that runs in its own runtime; calling it immediately returns `task<T>`, and `await` retrieves the result.

```rp
async func load(id: int) -> user {
    return fetch_user(id);
}

func main() -> void {
    // 先启动两个任务，再依次等待：两个任务真正并行。
    let a: task<user> = load(1);
    let b: task<user> = load(2);
    let first: user = await a;
    let second: user = await b;
    print(first.name + second.name);
}
```

- `async` may only modify module-level free functions; methods, `main`, and annotated functions cannot be async.
- A task starts running at the call site; a task that is never `await`ed keeps running in the background and its result is discarded.
- `await` accepts only `task<T>` and returns `T`; a given task can be awaited only once.
- A task has its own runtime: caller variables and closures are invisible, and parameters and return values are copied by value (closures cannot cross tasks).
- If a task fails, `await` rethrows the original error (including the function stack) to the caller.
- The scheduler creates 8..=64 worker threads based on 4× CPU cores; `await` first waits for a completion notification (about 200µs) so the task finishes on a scheduler thread, and only after that timeout does the waiter help execute it, so nested `await` never deadlocks.

### 5.2 HTTP Server

```rp
use std::http;

http.serve(port: int, handler: func(http.request) -> http.response) -> void
http.router(routes: vec<http.route>) -> func(http.request) -> http.response
http.get / post / put / delete / patch / options / head(path, handler) -> http.route
http.static(prefix: string, dir: string) -> http.route
http.group(prefix, middlewares, routes) -> http.route
http.chain(middlewares, handler) -> handler
http.cors(origin) / http.security_headers() / http.with_headers(map) / http.rate_limit(rate, burst)
http.openapi(handler, title, version) -> string
```

**Routing**: annotations take priority and are registered automatically when `http.router` is built; explicit routes such as static assets are passed in as arguments.

```rp
#[get("/users/:id")]
func show(read req: http.request) -> http.response {
    let id: string = req.params.get("id").unwrap_or("");
    return http.response[status = 200, json = [id = id]];
}

func main() -> void {
    let extra: vec<http.route> = [http.static("/assets", "public")];
    http.serve(8080, http.router(extra));
}
```

**Middleware**: a factory function `func(handler) -> handler`.

```rp

    -> func(http.request) -> http.response {
    return func(write req: http.request) -> http.response {
        let token: string = req.headers.get("authorization").unwrap_or("");
        if token == "" {
            return http.response[status = 401, body = "unauthorized"];
        }
        req.ctx.set("user", token);
        return next(req);
    };
}

    ])
]));
```

### 5.10 Concurrency Primitives

Threads do not share Rip variables; when state must be shared, use the `std/sync` **named** primitives: the same name denotes the same object in HTTP worker threads, `parallel` branches, `task.spawn`, and scheduled tasks.

```rp
use std::sync;

let lock: sync.mutex = sync.mutex("report_lock");
let counter: sync.atomic = sync.atomic("jobs_done", 0);
let jobs: sync.channel = sync.channel("jobs", 64);
```

**Mutex**: `lock()` / `try_lock()` / `lock_timeout(ms)` / `unlock()` / `is_locked()`. After acquiring the lock, release it with `defer`:

```rp
func write_report(text: string) -> result<void, string> {
    lock.lock();
    defer lock.unlock();      // 提前返回或出错也会释放
    fs.write_file("report.txt", text)?;
    return ok;
}
```

**Atomic integer**: `load()` / `store(v)` / `add(v)` / `sub(v)` / `swap(v)` / `compare_swap(old, new)`, all `SeqCst`; `add` / `sub` / `swap` return the old value.

**Channel** (bounded queue that transfers deep copies of values):

```rp
ch.send(value) / ch.try_send(value) / ch.send_timeout(value, ms)
ch.recv() / ch.try_recv() / ch.recv_timeout(ms)   // 返回 option<any>
ch.close() / ch.is_closed() / ch.len() / ch.capacity()
```

- When full, `send` blocks; `try_send` returns `false`; `send_timeout` waits at most `ms`.
- After close, queued values are drained first and `recv` then yields `none`; `send` fails afterwards.
- Received values are `any`; narrow them with `.as_int()` / `.as_string()` and the like.
- Every blocking operation checks the HTTP handler deadline every 20ms and aborts immediately on request timeout; background tasks should use `*_timeout` or `try_*` to avoid blocking forever.
- `sync.exists(name)` / `sync.remove(name)` inspect and clean up the registry; use fixed constants for the names.

```rp
// 生产者：后台任务
func worker() -> void {
    let jobs: sync.channel = sync.channel("jobs", 64);
    jobs.send(42);
}

// 消费者：超时轮询
task.spawn("worker");
let jobs: sync.channel = sync.channel("jobs", 64);
match jobs.recv_timeout(1000) {
    some(value) => { dev.log(value.as_int().unwrap_or(0).to_string()); }
    none => { dev.log("1 秒内没有消息"); }
}
```

### 5.11 Time Zones, Unicode, ZIP, and Mail

**Time zones**: a built-in IANA database (DST included) with no dependency on the system tzdata. Format strings match `time.format`; `%:z` prints `+08:00`.

```rp
match time.format_zone(ts, "%Y-%m-%d %H:%M:%S %:z", "Asia/Shanghai") {
    ok(text) => { dev.log(text); }
    err(message) => { log.error(message); }
}
match time.parse_zone("2024-07-01 08:00:00", "%Y-%m-%d %H:%M:%S", "Asia/Shanghai") {
    ok(ms) => { dev.log(ms.to_string()); }
    err(message) => { log.error(message); }
}
time.offset(ts, "America/New_York")     // ok(-14400)：夏令时已计入
time.zone_names() / time.local_zone()         // 全部时区名 / 系统时区名
```

- An unknown time zone returns `err` and never panics.
- Repeated instants during a DST fall-back resolve to the earlier one; instants skipped in spring return `err`.
- `time.format` / `time.parse` use the process-local time zone; use `*_zone` when you need determinism.

**Unicode**: `len` / `slice` count code points; grapheme clusters and display width are counted separately.

```rp
str.normalize(text, "nfc")        // nfc / nfd / nfkc / nfkd
str.graphemes(text)                 // vec<string>：emoji、组合音标不拆开
str.grapheme_len(text) / str.width(text)

"👨‍👩‍👧‍👦".len()              // 7（码点）
"👨‍👩‍👧‍👦".grapheme_len()     // 1（用户可见字符）
"中文".width()               // 4（终端列数）
```

**ZIP**: entry names must be relative paths; absolute paths, drive letters, and `..` are always rejected.

```rp
zip.create(path, files) -> result<int, string>          // map<string, string>
zip.add(path, files) -> result<int, string>
zip.list(path) -> result<vec<zip.entry>, string>
zip.extract(path, dir) -> result<int, string>
zip.read_text(path, entry) / read_base64(path, entry) / contains(path, entry)

match zip.create("dist.zip", ["a.txt" = "hello", "docs/b.txt" = "world"]) {
    ok(count) => { dev.log(count.to_string()); }
    err(message) => { log.error(message); }
}
```

- `zip.entry`: `name` / `size` / `compressed_size` / `crc32` / `is_dir`.
- Extraction and read limits: 256 MiB per entry, 2 GiB per operation (zip-bomb protection).
- `read_text` requires UTF-8; use `read_base64` for binary data.

**Mail**: `mail.config()` returns defaults, then override field by field; field types are checked by the compiler.

```rp
use std::mail;

let mut cfg: mail.config = mail.config();
cfg.host = "smtp.example.com";
cfg.port = 587;
cfg.tls = "starttls";                  // none / starttls / ssl
cfg.username = "bot@example.com";
cfg.password = "secret";                // 只在有 username 时使用
cfg.from = "bot@example.com";
cfg.to = ["ops@example.com"];
cfg.subject = "日报";
cfg.text = "纯文本正文";

match mail.send(cfg) {
    ok(_) => { dev.log("sent"); }
    err(message) => { log.error(message); }
}
```

- When both `text` and `html` are present the message is `multipart/alternative`; with attachments the outer type is `multipart/mixed`.
- Attachments use `mail.attachment()`: `filename` is required, and content comes from `content_base64` (preferred) or `path`.
- `timeout_ms` limits each socket operation; `mail.send` blocks, so inside an HTTP handler run it in a background function via `task.spawn`.

Imports use Rust-style `use` with `::`-separated paths; calls still follow Rip's `module.function()`:

```rp

The repository's `editors/vscode/` provides syntax highlighting, LSP (`rip lsp`), and DAP debug configurations; `rip.executable` sets the toolchain path.

**Performance**: `rip profile main.rp` lists functions sorted by total time once the run ends; `--top 0` shows all of them and `--json` makes CI integration easy; closures and `std/*` calls are counted too.

**Cross-compilation**: `rip build --target x86_64-unknown-linux-gnu` uses cargo to build the runtime for the target platform and produce the binary; you must first run `rustup target add <triple>` and configure a linker in `.cargo/config.toml` or via `RIP_TARGET_LINKER` (C dependencies such as sqlite / openssl also need a matching cross toolchain). When target and host match, the built-in compiler fast path is still used.

**Build artifacts**: by default `rip build` places the executable, static assets, data directories declared by `[build] copy`, and the README into `dist/`; the `flat` layout keeps everything at the root, while the `typed` layout splits it into `bin/`, `data/`, and `share/`. The delivery directory only needs the executable to run.

**Runtime configuration**: dropping `config/rip.toml` next to the executable overrides `[server]` / `[runtime]` / `[db]` and other settings without recompiling; environment variables such as `RIP_SERVER_HOST` and `RIP_SERVER_WORKERS` are also supported.

## 8. Building Your Own Standalone Package

### 8.1 Package Layout

```text
packages/acme/tools/
├── rip.toml        # [module] name / version 必填
└── tools.rp        # mod tools;
```

On the importing side:

```rp
use acme::tools;
tools.slugify("Hello World");
```

- The directory name (`tools`) must equal the `mod tools;` declared in the file.
- Only `pub` functions / types can be used across packages; `self func` is private to the package.
- After merged compilation every function and type name is globally unique, so prefix names with your domain to avoid conflicts.

### 8.2 Writing and Publishing

```rp
mod tools;

pub func slugify(text: string) -> string {
    return str.lower(str.replace(str.trim(text), " ", "-"));
}

self func internal_note() -> string {
    return "not exported";
}
```

```bash
rip check packages/acme/tools/tools.rp     # 本地检查
rip pack packages/acme/tools               # 生成 tools.rpa 预编译包
rip pub packages/acme/tools --registry https://pkg.example.com
```

- Before publishing you must declare `rip.toml` with `[module] name` and a valid `version`; publishing the same version twice is an error.
- Consumers declare dependencies with semantic version constraints:

```toml
[dependencies]
acme/tools = "^1.2"
```

```bash
rip add acme/tools@^1.2      # 写清单并立即拉取到 packages/
rip vendor                   # 只拉取依赖（离线构建用）
rip lock --check             # CI 校验锁定版本
```

- After `rip pack` produces a `.rpa` you may delete the source; imports stay the same.
- Built-in Rust packages use `use rust::serde_json as json;` and are called exactly like ordinary packages.

## 9. Deployment Essentials

```bash
rip build main.rp -o release
# 服务器上：
./shop --host 0.0.0.0 --port 8080
```

- External listening requires an explicit `--host 0.0.0.0` (only loopback is bound by default).
- HTTPS: `--cert` and `--key` must be supplied together.
- Built-in probes: `/healthz` (liveness) and `/readyz` (readiness); Prometheus metrics are exposed when `metrics_path = "/metrics"`.
- Behind a reverse proxy, enable `trust_proxy = true` or configure `trusted_proxies` so the client IP comes from `X-Forwarded-For`; enabling `trust_proxy` without `trusted_proxies` prints a spoofing warning at startup.
- Tracing: with `otlp_endpoint = "http://127.0.0.1:4318"` OTLP/HTTP traces are exported automatically, and `trace_id` in logs correlates directly.
- For rate limiting configure `rate_limit` / `rate_limit_burst`; requests beyond it get `429`.

Minimal systemd example:

```text
[Unit]
Description=shop
After=network.target

[Service]
WorkingDirectory=/srv/shop
ExecStart=/srv/shop/shop --host 0.0.0.0 --port 8080
Restart=always

[Install]
WantedBy=multi-user.target
```

## 10. Common Errors

| Error | Cause | Fix |
| --- | --- | --- |
| mod name 'x' must match directory name 'y' | The `mod` name differs from the directory name | Rename `mod` to the directory name |
| every .rp file in directory ... must start with 'mod ...;' | Missing module declaration | Add `mod directory_name;` on the first line |
| type mismatch for 'x': expected string, found int | Type mismatch | Convert explicitly with .to\_string() / .to\_int() |
| cannot assign to immutable variable | Assigning to a let variable | Change it to let mut |
| use of moved value | The value was already passed by value | Call .clone() before passing, or declare the parameter as read |
| ? can only be used in a function returning result | The function does not return result | Change the signature or use match |
| match is not exhaustive | Missing some/none or ok/err | Add the missing arms |
| match arm uses '=\>', not '=' | A match arm was written with = | Change it to `=>` |
| for requires \`for \<name\> in \<vec\|map\>\` | A conditional or C-style for was used | Use `while` / `loop` / `for x in y` |
| type vec\<T\> has no method 'x' | Misspelled method name | Check the method table in section 4 |
| v[0] fails to compile | vec does not support subscripts | Use v.0 or v.at(i) |
| scores["k"] fails to compile | map does not support subscripts | Use scores.get("k") |
| route handler must take exactly one http.request | Wrong route handler signature | Use func(read req: http.request) -\> http.response |
| package "std/x" is not available | Not imported, or the module name is wrong | Add `use std::x;` |
| unknown attribute '#[x]' | Invalid annotation name | Only route, interval, test, and bench are supported |
| decimal integer literal cannot initialize string | The literal does not match the type | Add quotes or convert explicitly |

## 11. Complete Examples

### 11.1 JSON API (routing + validation + JWT)

```rp
mod api;

use std::http;
use std::jwt;
use std::validate;

static SECRET: string = "change-me";

#[post("/login")]
func login(read req: http.request) -> http.response {
    let name: string = req.form.get("name").unwrap_or("");

    match validate.string_len(name, 1, 32) {
        ok(valid) => {
            let token: string = jwt.sign(["sub" = valid], SECRET, 3600);
            return http.response[status = 200, json = [token = token]];
        }
        err(message) => {
            return http.response[status = 400, json = [error = message]];
        }
    }
}

#[get("/me")]
func me(read req: http.request) -> http.response {
    let token: string = req.headers.get("authorization").unwrap_or("");
    match jwt.verify(token, SECRET) {
        ok(claims) => { return http.response[status = 200, json = some(claims)]; }
        err(message) => { return http.response[status = 401, body = message]; }
    }
}

func main() -> void {
    let routes: vec<http.route> = [];
    http.serve(8080, http.router(routes));
}
```

### 11.2 Paged Queries (ORM)

```rp
func list_users(read conn: db.conn, page: int, size: int) -> result<vec<map<string, any>>, string> {
    let offset: int = (page - 1) * size;
    return db.table(conn, "users")
        .field("id, name, email")
        .order("id", "desc")
        .limit(size)
        .offset(offset)
        .select();
}
```

### 11.3 Scheduled Tasks + Queues

```rp
#[interval("30s")]
func send_mail() -> void {
    match queue.reserve("storage/jobs.db", "mail", 60000) {
        ok(job) => {
            match job {
                some(item) => {
                    // 调用邮件服务；失败时交给队列重试
                    if item.attempts > 3 {
                        queue.fail("storage/jobs.db", item.id, "too many attempts");
                    } else {
                        queue.ack("storage/jobs.db", item.id);
                    }
                }
                none => { }
            }
        }
        err(message) => { log.error(message); }
    }
}
```

## 12. Dependency Management: rip vendor

> This section is merged from the rip vendor User Guide and covers the commands and workflow from a user's perspective.

`rip vendor` completes the third-party packages declared in `[dependencies]` (transitive dependencies included) into the project's `packages/` directory and freezes the current dependency state into `rip.lock`.

In one sentence: **a freshly cloned repository can build exactly the same dependencies as the original author, with no network access.**

---

### 12.1 Command

```bash
rip vendor            # 拉取缺失依赖，生成/更新 rip.lock
rip vendor --check    # 只校验，不写入（CI 用）
```

| Item | Description |
| --- | --- |
| Working directory | Must be a project root containing rip.toml |
| Global options | --offline (no network; missing packages fail immediately), --deny-warnings |
| Exit code | 0 success; 1 dependency or checksum failure; 2 not a Rip project |

Normal output:

```text
vendored 2 package(s) into .\packages; wrote .\rip.lock
```

When there are no dependencies:

```text
no packages to vendor; wrote .\rip.lock
```

When verification passes:

```text
rip.lock: ok (2 packages)
```

---

### 12.2 Quick Start

`rip.toml`:

```toml
[module]
name = "app"
version = "0.1.0"
entry = "main.rp"

[registry]
source = "https://registry.example.com"

[dependencies]
"acme/tools" = "^1.2"
```

```bash
rip vendor
```

After running:

```text
app/
├── rip.toml
├── rip.lock
└── packages/
    └── acme/tools/
        ├── .rip-registry     # 由 rip 写入的来源标记
        ├── rip.toml
        └── tools.rp
```

Commit `packages/` together with `rip.lock` and the repository can build offline.

---

### 12.3 What It Does

`rip vendor` performs three steps in order (sharing one implementation with `rip lock`):

- Already present locally and satisfying the constraint → no network access.
- Missing locally or not satisfying it → fetched from `[registry]`.
- If the package is already in the lock file, the locked version is preferred, guaranteeing reproducibility.

1. **Validate constraints**: version ranges, conflicts between multiple constraints on the same package, and completeness of transitive dependencies.
2. **Freeze the result**: scan `packages/`, aggregate by **package directory**, and write `rip.lock`.

`packages/` is itself Rip's vendored directory, so "fetching" and "locking" are the same action here.

---

### 12.4 Lock File Format

```toml
# generated by 'rip lock'; do not edit
version = 1
registry = "https://registry.example.com"   # 仅当配置了 [registry] source

[[package]]
name = "acme/tools"                # 包目录相对 packages/ 的路径
version = "1.4.0"                  # 来自包内 rip.toml 的 [module] version
source = "packages/acme/tools"     # 本地目录
sha256 = "26c1200f1fb6…"           # 包目录内全部文件的摘要
deps = ["acme/base"]               # 直接依赖的包名
```

A few conventions:

- **One record per package directory**. Multiple `.rp` files in the same directory belong to one package and never appear twice.
- **Package name = directory relative path**, consistent with `use acme::tools;` and with the keys of `[dependencies]`.
- **The checksum covers the whole directory**: entries are sorted by relative path and "path + file content" is hashed with SHA-256, so multi-file packages verify stably.
- Do not edit it by hand; re-run `rip vendor` when an update is needed.

---

### 12.5 Verification Rules

`rip vendor --check`, as well as `rip run` / `rip dev` / `rip build` / `rip check` / `rip test`, verify the lock file when reading the project:

| Situation | Message |
| --- | --- |
| Lock file missing | rip.lock is missing; run 'rip vendor' to generate it |
| Package content modified | package 'x' does not match rip.lock |
| Package version changed | package 'x' version changed from 'a' to 'b' |
| Direct dependency list changed | package 'x' dependency list changed |
| A locked package disappeared | package 'x' from rip.lock is missing |
| packages/ contains an unrecorded package | package 'x' is not recorded in rip.lock |

If any of the above appears, run `rip vendor` again.

> Note: `--check` requires an existing lock file. For a newly cloned repository, run `rip vendor` once first.

---

### 12.6 Typical Workflows

#### Adding dependencies for the first time

```bash
rip add acme/tools@^1.2   # 写入 rip.toml 并立即拉取
rip vendor                # 生成 rip.lock
```

Commit `rip.toml`, `rip.lock`, and `packages/`.

#### Cloning a new repository

```bash
rip vendor     # 还原 packages/ 与 rip.lock
rip run main.rp
```

If `packages/` is committed with the repository, this step never touches the network.

#### Upgrading dependencies

```bash
# 修改 rip.toml 的约束，例如 ^1.2 -> ^1.3
rip vendor
```

- When the old locked version still satisfies the new constraint, it is kept (preserving reproducibility).
- When the old version does not satisfy the new constraint, a backtracking solve runs again from the registry under the dependency constraints (only one version per package); when there is no solution, the origin of each constraint is reported.

#### CI

```bash
rip vendor --check
```

Verification only, no writes; if the lock file disagrees with `packages/`, a non-zero exit code is returned.

Security advisories and licence checks: `rip audit --deny high --licenses` (advisories come from `[registry] advisories` / `RIP_ADVISORIES` / `<source>/v1/advisories.json`); to inspect the registry use `rip search <keyword>` and `rip info <package name>`.

Fully offline environments:

```bash
rip vendor --check --offline
```

---

### 12.7 Relationship to the Registry and Offline Mode

- The registry is set by `[registry] source` and supports `https://`, `file://`, and local directories; `http://` is allowed only for `localhost` / `127.0.0.1` / `::1` (local development), and any other http source is rejected outright. Downloads from a remote source must carry an index `sha256`; a missing digest is rejected. When unset, the public registry `https://registry.rip-lang.dev` is used and can be overridden with the `RIP_REGISTRY` environment variable (`rip pub` still needs an explicit target and never falls back to the public registry); when all dependencies are vendored, the registry is never contacted.
- Access tokens: `[registry] token_env = "MY_TOKEN"` names the environment variable; if unset, `RIP_REGISTRY_TOKEN` is read.
- With `--offline` or `[registry] offline = true` there is no network access; missing dependencies then fail immediately:

```text
  error: package 'acme/tools' is not vendored and network access is disabled
```

- Package directories fetched by rip contain a `.rip-registry` marker; packages **placed into `packages/` by hand are never silently overwritten** — delete them first or adjust them to a matching version.

---

### 12.8 FAQ

**Q: Should `packages/` be committed?**

Either way works:

- Commit: fully offline builds, at the cost of a larger repository;
- Do not commit: restore from the registry with `rip vendor`, which requires access to `[registry]`.

**Q: What is the difference between `rip vendor` and `rip lock`?**

Resolution and writing are identical. The output of `rip vendor` focuses on "how many packages were vendored", semantically emphasizing that dependencies are frozen into `packages/`; both generate byte-for-byte identical lock files.

**Q: Why did nothing upgrade after I changed the constraint?**

Because the locked version still satisfies the new constraint. To force re-selection, delete the corresponding record from `rip.lock` (or delete the whole lock file) and run `rip vendor` again.

**Q: It reports `already exists under packages/ ... was not fetched by rip`?**

That directory was placed by hand. Delete it so `rip vendor` fetches the package again, or adjust the `[dependencies]` constraint to match the version in that directory.

**Q: It reports `checksum mismatch`?**

The zip returned by the registry does not match the `sha256` in the index. Check whether the registry content was replaced, or contact the registry maintainer.

**Q: How do I publish my own package?**

`rip vendor` only consumes dependencies. To publish, use `rip pub`; see Chapter 7, "Compiling, Running, Packaging, and Publishing".
